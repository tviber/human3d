# Human3D 界面设计原则

## 产品结构

- **动作观察是默认入口**：打开动作、理解阶段、旋转视角、逐帧查看。主视图优先给人体和时间轴。
- **动作工作台是进阶创作区**：从支持编辑的动作显式创建副本，再编辑、检查和导出。预设源不被隐式改写。
- **研究与动力学是按能力出现的观察内容**：只在动作确实包含对应记录时展示；持续标明工程近似、记录来源和适用边界，不暗示临床测量或个体评估。
- 页面与操作名称描述当前真实能力，不引入尚未实现的课程、云项目、协作或通用研究档案概念。

## 视觉语言

- 采用明亮中性画布、清晰石墨文字、细边界和蓝色交互强调，形成简洁、精确、面向工具的界面。
- 3D 人体是最重要的视觉对象。UI chrome 保持安静，颜色用于当前选择、焦点与明确的语义状态。
- 用字号、留白、对齐和稳定的分区建立层级，避免连续嵌套卡片、装饰性渐变和大面积阴影。
- 页面标题 20–32px，面板标题 14–16px，常规控件与说明 12–14px；关键数值使用等宽数字。重要信息不得只用浅灰小字表达。
- 控件焦点清晰可见，键盘、鼠标和触屏都保留明确入口；交互目标按其操作密度提供足够点击区域。
- 动效简短、不弹跳，尊重 `prefers-reduced-motion`。

## 页面层级

### 动作观察

- 桌面：动作库 / 3D 视图 / 观察与数据面板 + 固定播放条。
- 画布标题、相机、加载状态和适配视图使用轻量浮层；阶段与时间码在播放条内易读。
- 观察面板先呈现通用显示与当前动作读数；动力学、肌腱和模型依据仅在支持时加入。
- 小屏沿用视口优先的底部抽屉，不把所有设置堆成纵向长页。

### 动作工作台

- 桌面：动作与常用关键帧工具 / 3D 编辑画布 / 选中关键帧检查器 + 固定时间轴。
- Review 默认只读；明确进入 Edit 后才启用写入。画布手柄、语义控件和精调控件必须继续走同一份真实动作文档、撤销与自动保存路径。
- 语义调整优先；精确关节、坐标、约束和通用动作属性在明确分组内呈现。
- 备份恢复、组合、候选生成、参考视频和高级导出按需展开，但必须可发现、状态透明。
- 小屏通过 CSS 将相同画布和面板改为抽屉，抽屉开合不得重建 Three.js 场景或丢失视角/编辑状态。

## 时间轴交互

- 播放头移动始终对应连续时间；点击工作台空轨道时，鼠标落点距最近关键帧不超过 14 CSS 像素则吸附并选择该帧。
- 点击关键帧标记始终选择该帧；在轨道上拖动播放头继续连续 scrubbing，不吸附，以便观察帧间姿态。
- 触屏沿用现有较大关键帧命中区和拖动阈值，不改变关键帧重定时语义。
- 阶段标记是导航快捷入口；点击阶段直接定位到其定义时刻。

## 数据与编辑边界

- 外部 clip、动力学记录、自建文档和姿态包保持各自来源语义；只在能力支持时提供编辑入口。
- 候选生成、语义预览、危险备份恢复和导出校验沿用既有取消、确认、撤销与错误提示规则。
- 任何视觉改造不得绕过 `docs/domain/workshop.md` 所列的接触区间、撤销隔离、持久化和真实写路径不变量。

## 实现位置

共享设计 token 位于 `src/theme/tokens.css`，共享页面刷新位于 `src/redesign.css`；实验室样式在 `src/style.css`，工作台样式在 `src/workshop/workshop.css`。
