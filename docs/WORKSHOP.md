# 动作工作台（Motion Workshop）

状态：已实现最小可用版（`workshop.html`），轨迹优先，不依赖 MuJoCo 动力学。

## 为什么先做轨迹而不是肌肉

查看器接入 MyoSim/MuJoCo 的正向链路是「肌肉激活 → 关节力矩 → 物理积分 → 动作」。但动画素材与运动分析真正需要的是**动作轨迹**：先有目标姿态再倒推肌肉收缩，会立刻撞上逆动力学、肌肉冗余控制（数百条肌肉 ↔ 几十个自由度）和运动规划三个难题，仅靠手工关键帧无法唯一确定驱动方式。

MyoSuite 官方文档本身就把运动回放（joint-angle trajectory replay）、逆运动学、逆动力学、正向模拟分成不同操作——载入关节角轨迹回放不要求从肌肉激活开始。

因此工作台把管线重排为：

| 阶段 | 方法 | 需要动力学 |
|---|---|---|
| 手动调整关键姿态 | 任务空间拖动 + 解析 IK | 否 |
| 生成连续动作 | 关键帧区间可选平滑 Hermite 或线性补间 + 约束保持 | 否 |
| 更自然的动作 | 参考视频对照（后续：WHAM/Motion Prior） | 否 / 可选 |
| 物理合理性 | 关节限位、支撑脚锁定、重心投影检查 | 运动学近似即可 |
| 真正肌肉控制 | MuscleMimic / 物理模仿学习 | 是 —— 后续阶段，不重造 |

MuscleMimic（amathislab/musclemimic）已提供全身肌肉驱动模仿学习实现与预训练检查点；当轨迹确认后再把「哪些肌肉实现了这个运动」交给它，而不是手工推激励。

## 交互模型

**1. 拖动末端而不是逐关节旋转。** 手腕、脚踝、骨盆、拍头都是可拖动手柄，命中后由定长双骨 IK（`solveTwoBone`）解算整条链；肘/膝极点手柄调弯曲平面朝向。拖动写进当前或自动新建的关键帧（auto-key）。

**2. 关键帧携带约束而不只是姿态。** 每个关键帧记录：

- `plantL / plantR`：支撑脚锁定。连续的 `plant=true` 关键帧构成一个**接触区间**：整个区间内脚保持在区间起始帧的接触位置（后续锁定帧存储的脚位被忽略——接触是约束不是姿态采样）。移动支撑脚必须先经过一个 `plant=false` 关键帧（离地），再声明新的 `plant=true`（重新接触）。离地帧时刻脚仍位于上一接触点（保证连续），但**离地帧存储的脚位不会被忽略——它作为摆动路径点**：脚从接触点出发，在区间中点经过该存储姿态，再到落地帧接触点。默认平滑 Hermite 模式下切换处速度连续；选线性时速度可能在关键帧或摆动中点改变，但位置仍连续。
- `grip`：握拍约束（侧别由文档级 `gripSide` 决定）→ `applyGrip` 包裹该侧指节、球拍挂载到该侧手腕。
- `contact`：触球/接触事件 → 拍头在该帧的世界位置显示为黄色标记，直接拖动标记即调整该帧手部目标让拍头到达该点（写入握拍侧的手部目标）。

约束属于关键帧并随 JSON 导出——生成器由此知道动作的**目的**（支撑、接触时刻），不只是身体形状。

**3. 参考视频并排。** 本地视频载入（不上传），帧步进、「对齐」把视频时间轴对齐到动作时间轴、可同步播放；每个关键帧可记录其对应的视频时间，形成视频关键帧清单。WHAM 类单目 3D 重建是后续接入点（遮挡、深度歧义需人工修正），当前以人工对照关键帧为主。

**4. 洋葱皮对照。** 「显示」卡片开启后，编辑视图叠加相邻姿态的幽灵骨架线框（`LineSegments`，非克隆 SkinnedMesh）：`keys` 模式取播放头前后各 N 个真实关键帧时刻（`sortedKeys` 括号定位，压在播放头下的键不幽灵化——那是正在编辑的实姿态），`step` 模式取 `t±k·Δt` 随播放头每帧跟随。每个幽灵时刻走与轨迹采样相同的 `frameAt + solveEffectiveFrame` 真实求解路径再逐骨记录世界位置。前帧冷色、后帧暖色、按距离衰减透明度，`depthTest:false`、renderOrder 8（低于手柄的 20）、不进拾取集合。每向最多 3 层——120 键文档不会被全键幽灵化；重算挂在 `docDirty`/`rebuildAux` 节奏上，幽灵时刻签名不变则跳过重解算，拖动中冻结。开关与参数是会话态，不写入动作库。

**5. 审阅 / 编辑与手机布局。** 视图左侧「审阅 / 编辑」切换：审阅模式隐藏手柄、锁定姿态控件，单指旋转、双指缩放/平移绝不写入动作；编辑模式才可拖手柄（触摸时最近 28 px 内的手柄命中，几何不变）。窄屏（≤760px 或触屏短边横屏）为三维视图 + 底部快捷条（动作 / 调整抽屉、轨迹、洋葱皮、重心、手柄、全视野、参考视频画中画）；时间轴关键帧有 32×48 px 命中区，横向拖动 6 px 后才重定时，另有上一/下一关键帧按钮。

**6. 语义调整。** 选中关键帧「语义」页：部位（肩/大臂、肘、前臂、手腕、髋/大腿、双腿、膝/小腿、踝/足、躯干）→ 左/右 → 方向（前屈/后伸、外展/内收、屈曲/伸展、旋前/旋后、掌屈/背伸、尺偏/桡偏、大腿向前/向后、大腿向外/向内、两腿分开/并拢（两大腿夹角）、背屈/跖屈、足尖外展/内收、前倾、转体、侧弯）→ ± 步进（1/5/15°）或滑块。每次预览经生产求解读回真实角度变化，显示请求值、实际值、残差、腕目标残差与支撑脚位移；限位或不可达时写明原因。每个部位只转动它自己的关节：大臂转动时肘角、腕角与手的相对朝向不变，大腿向前 / 向外时膝角与踝角不变，小腿转动时踝角不变（下方各段刚性随动）。支撑锁定帧上调髋或膝会让该脚离开接触点：本帧改为离地并使用新脚位，前一 / 后一关键帧接管原接触点，其显示姿态保持不变（报告里写明）；自动骨盆后移在此保持不变，避免整个身体被带动。被带动的子关节超过 1.5° 或脚底穿地时标为未完全执行。腿部页有「落地」按钮：本帧身体（骨盆、双手、离地的脚、膝 / 肘引导点）整体竖直平移，直到所选腿的脚底贴地；调整过的关节角不变，仍在支撑的腿重新求解并报告膝角变化，支撑腿够不到接触点或支撑踝背屈超过 20° 时不落地并说明原因；一次落地是一条撤销记录，不改其他关键帧。「确认」为一条撤销记录，「取消」恢复。实现：`packages/motion-core/src/semantic-edit.ts`。

**7. 审阅反馈。** 「审阅反馈」卡按关键帧标记部位与问题（手臂穿身、拍头方向、支撑脚漂移等），复制为结构化 JSON 交给 agent；仅存于会话，不写入动作文档。

**显示皮肤。** 实验室与工作台的人体表面使用肌肉分区着色（`apps/web/src/theme/anatomy-skin.ts`：按蒙皮主骨与法线分组、肌腹向肌腱渐变、分界沟槽、纤维条纹）。这是展示近似，不是解剖图谱；几何、权重、求解与导出不变（GLB 导出重新解析干净模型）。

## 数据与求解

- `packages/motion-core/src/document.ts`：`WorkshopDoc` = 关键帧数组 + 时长 + 补间开关。姿态是任务空间参数（根骨偏移/朝向、脊柱前倾/转体/侧弯、四肢末端目标 + 极点 + 手部 forward/normal 框架、脚部 yaw/pitch）。`samplePose` 按数据性质分别插值：位置量做非均匀 Hermite（Catmull-Rom 中心差分切线，每个内部键限界 `|m| ≤ 2×相邻较小割线幅值`（`TANGENT_SECANT_CAP`）——抑制稀疏键的样条过冲/鞭打，端点与锁定通道仍取零切线，保持 C¹）；yaw/foot yaw/pitch 等角度先沿关键帧链做 ±360° 展开再走最短路径；手部 forward/normal 契约上必须是正交归一框架（seed/parse/库存恢复时规范化），按 corrected-slerp 形式的 SO(3) 三次曲线插值（逐位过键、键时刻角速度 C¹，切线与 `tan()` 同一构造与同限界）保证中间帧始终构成有效方向；支撑脚按上一条接触区间规则保持。
- `packages/motion-core/src/solver.ts`：采样帧的唯一求解入口是 `solveEffectiveFrame`（支撑权重淡入淡出、握拍渐变、抬肩辅助随帧传入，不再单独推导），落到 `solvePose` 把参数写到骨架（复用 `rig.limb`/`rig.hand`/`applyGrip`，含支撑脚背屈超限时的骨盆后移二分修正）。`analyzePose` 输出运动学合理性：膝/肘/肩限位、支撑脚残差、分段质量近似质心在支撑多边形（锁定脚脚印凸包）内的投影。
- `apps/web/src/workshop/engine.ts`：Three.js 场景、手柄拾取与拖拽平面、轨迹线（拍头/手腕）、触球标记、质心投影与地面支撑多边形。
- `apps/web/src/workshop/WorkshopApp.tsx`：文档/视频/约束/检查面板 + 关键帧时间轴。
- `mirrorDoc`（`document.ts`）整档镜像：以 x=0 平面（该骨架左=+X、右=−X）把同一动作换边——右手正手变左手正手。逐键约定：`root.x`、骨盆 `yaw`、`chest`/`side`（YXZ 中的 Y/Z 分量）与脚 `yaw` 取反，`lean`、脚 `pitch` 保持；`handL⇄handR`、`footL⇄footR` 对调且 target/pole/forward/normal 全部 x→−x（正交框架逐位保持）；`plantL⇄plantR` 对调使接触区间挪到另一侧脚（接触点、离地帧摆动中点经同一存储重写随动镜像）；`handFrames` 随手换侧（惯用的双手 pelvis 配置下等价于不变）；`gripSide` R↔L 翻转（镜像回右手时写回规范缺省形态）；`clavicleLift`、`loop`、`duration`、`inbetweens`、键时间/标签/`videoTime` 原样保留；`id`/`name`/`english` 追加可回切的镜像标记（`.mirrored` / ` · 镜像` / ` · MIRRORED`）——再镜像一次逐字节回到原文档。文档卡「镜像动作」按钮把镜像文档作为**新动作**入库并选中（原文档保留），且在新文档的撤销书上预存源文档快照：一步撤销即回到镜像前的文档（选择跟随恢复的 id；重做对称地回到镜像文档）。跨文档恢复是**指针语义**：只切换选中，快照内容绝不写回异 id 文档——否则镜像后对源文档的新编辑会被旧快照无提示抹掉。`mirror.test.ts` 在真实 `frameAt → solveEffectiveFrame` 路径上逐骨断言世界位置/朝向互为 x 镜像（实测位置残差 ≤2.8e-15 m、朝向 ≤6e-8 rad），随机文档与 shipped 资产同口径覆盖。

## 动作库与存储

工作台与实验室共用本机动作库。手工编辑会自动保存，也可点击「保存到动作库」确认；保存的动作出现在实验室动作库顶部，可播放、回到原文档继续编辑或删除。内置预设保留原样。实验室只读加载不会创建默认文档或覆盖损坏数据；删除最后一个自建动作后列表可为空，工作台下次打开会创建新的空白工作区。

### 拼接与混合

左侧「组合动作」选择另一段自建动作或内置关键帧动作，再选择组合方式和可选名称，点击「拼接并保存 / 混合并保存」创建新动作。两份源文档保留；新文档沿用镜像动作的撤销规则，第一次撤销切回源动作，后续编辑可正常撤销。

- 前后拼接：当前完整动作 → 0.1–2 秒过渡（默认 0.3 秒）→ 另一段完整动作。总时长超过 10 秒时拒绝，源动作不变。
- 按比例混合：两段动作按归一化进度对齐，取较长时长；滑块指定另一段占比。0% / 100% 是对应源的独立副本；其余比例生成不循环的关键帧动作。支撑仅在双方都支撑时保留；握拍与触球事件取占比高的动作，50% 取另一段。
- 组合使用生产采样器读取姿态、短弧角度和手腕旋转，再以最多 120 帧重建可编辑文档；优先保留支撑 / 握拍切换和触球时刻，空间充足时保留源关键时刻，额外采样最高约 12 Hz，因此中间轨迹为近似值。离地键存储下一小段的摆动中点，持续支撑保持锚定。结果移除源视频时间标记。
- 一个文档只有一套自由手臂、锁骨辅助和持拍侧设置。两段策略不一致、或双方均持拍但侧别相反时，提示先统一设置 / 镜像；必要的约束切换与触球时刻合并已超过 120 帧时拒绝。外部剪辑和动力学回放没有可编辑文档，不列入组合来源。
- 保存仍使用同一本机动作库，存储不可用或已满会明确报告失败；内存中的组合结果可导出 JSON 备份。

### 关键帧管理

左侧「关键帧」列表按时间排列，可滚动查看整段动作。点击一帧会暂停播放并定位到该帧；右侧三个调整页共用「帧名称」「时间 s」「顺序」字段，名称同步显示在列表、时间轴与阶段标签中。时间在失焦或按 Enter 后提交，Escape 取消本次输入；不能与其他帧重时，循环首帧固定在 0s。

- 「当前时刻添加」保存当前采样姿态；该时刻已有帧则直接选中。显式添加按 1µs 容差判重，不会被拖动自动建帧的 20ms 吸附吞掉。
- 「在选中帧后插入」在选中帧与下一时间点之间采样新增；已到动作末端时可延长 0.2s，最长仍为 10s。最多 120 帧，在写入入口拒绝超限。
- 每行的复制按钮或「复制选中帧」会把源帧完整复制到后方，并自动选中副本：姿态、约束、出段曲线与视频参考均独立保留，名称追加「副本」，生成新 id。插入时间沿用上述规则，原帧和其他帧时间不变；复制与必要的时长延长共用一条撤销记录。
- 列表的上移 / 下移与右侧「顺序」菜单保留原有时间槽，移动整帧的名称、姿态、约束、出段曲线和视频参考。直接修改时间则按新时间重新排列。
- 删除后至少保留两帧；循环首帧被删除时，下一帧移到 0s 保持循环锚点。删除选中帧后选中相邻帧。
- 插入、删除、换序及提交时间各自是一条撤销记录，连续点击也可逐步撤销；通过现有动作库自动保存与 JSON 导出保留。

### 快速姿态 · 球拍 · 我的姿态

关键帧列表下方是三行一键控制，全部从播放头所在状态出发、各生成一条结构化撤销记录：

- **快速姿态**：内置基础动作（半蹲、全蹲、弓步、重心转移、蹬转、侧开腿半蹲、体前屈、双手高举）每键一钮，点击即在播放头插入该动作（同「插入基础动作」语义：从当前姿态开始相对偏移，后续关键帧整体后移）。偏移按播放头姿态的 yaw 旋转成**身体相对方向**——角色朝向改变时，"前伸/旁开"仍沿人体自身的前方与侧方（朝向不变性有测试钉死）。其中体前屈与双手高举在信封上声明 `carryHands:true`——插入时手部目标/极矢量随模板偏移平移，手腕朝向保留当前姿态；其余动作手臂完全不动。数值上限由 `assets/motions/` 探针校准（臂全长约 0.53 m、踝背屈 20° 守卫），描述与实测残差一致。
- **球拍**：「右手持拍 / 左手持拍」把 `gripSide` 设为对应侧并给所有关键帧打开 `constraints.grip`（球拍全程显示）；「卸下球拍」清空全部握拍标志并把侧别归位默认。均为单步撤销。
- **我的姿态**：选中任意关键帧后「存当前姿态」把完整姿态（含手臂，不含约束）存入本机 `localStorage['kinesis-workshop-poses']`（重名自动编号，损坏条目读取时丢弃）；点击自建姿态把它写到播放头——该时刻已有帧则原位替换姿态（约束不变），否则插入新帧；右侧 × 删除。若目标帧的某侧脚是支撑区间的**非锚点成员**（前一帧也在支撑），该侧脚部的 target/yaw/pitch **不会被写入**（contactPlan 把整条通道锚定回支撑首帧，写了也不生效），提示里会如实列出，膝盖方向（pole）仍会应用；要移动支撑脚请先释放该帧支撑。**离地边界帧**（紧随支撑帧的 released 帧）则相反：离地瞬间脚仍从原接触点起步，但该帧存储的 target 是 `interpolate` 的摆动中点路点（contact → waypoint → 下一目标 的两段 Hermite），所以新目标会**写入并塑造离地后的摆动路径**；脚尖 yaw/pitch 没有路点机制、始终跟随支撑接触点（只改朝向的盖章不写入也不提示）。时间轴末尾的离地帧（后面没有摆动区间）按支撑成员处理。提示会说明这一语义区别。完全支撑的循环动作首帧是锚点、可正常编辑。「粘贴姿态」与「我的姿态 → 应用」共用同一套盖章语义（`stampPoseIntoKey`）。应用被关键帧上限拒绝时不产生撤销记录。「复制姿态 / 粘贴姿态」是会话内剪贴板，跨帧、跨动作均可粘贴。「镜像姿态」把选中帧左右镜像（`mirrorKey`：手脚与支撑互换；左右手坐标系不同时拒绝并提示改用整档「镜像动作」）。`gripSide` 是文档级属性，单帧镜像**不换**握拍侧（球拍仍挂在原侧手上，其他帧的握拍求解不受影响）；要整档换边请用「镜像动作」。动作库被删除时自建姿态不受影响；写失败时提示「仅存于内存」。

工作台按**动作库**组织（`apps/web/src/workshop/library.ts` 的 `MotionLibrary`）：

- 每个动作是一份 `WorkshopDoc`（`schemaVersion:2`）：`id`（按名称生成 slug + 随机后缀，冲突时重新生成）、`name`（自定义命名）、`english`、`duration`、`inbetweens`、`loop`（周期性接缝）、`handFrames`（手部目标按 world / pelvis 系插值）、可选 `clavicleLift`（抬肩辅助：握拍侧手部目标抬高时锁骨与肩带随动上抬，求解器逐帧推导幅度——内置 reach 动作使用，面板「抬肩辅助」开关）、可选 `gripSide`（握拍侧 `'R'|'L'`：缺省即右手且为规范形态——显式 `'R'` 在 `normalizeDoc` 归一化时折叠回缺省，因此同义写法共享指纹；`'L'` 把整套握拍阶段——`applyGrip` 指节包裹、腕弯曲限位、抬肩辅助、球拍挂载——镜像到左手，面板「握拍侧」下拉。侧别改变求解出的轨迹，所以它属于文档并进入请求指纹，不是展示元数据）、`keys[]`。关键帧可带可选 `interpolation`（`hermite` / `linear`，缺省 `hermite`），控制本帧到下一帧的过渡曲线。
- 动作库整体存 `localStorage['kinesis-workshop-library']`：`{schemaVersion:2, activeId, docs[], quarantine[]}`（只接受 schemaVersion 2 的容器与 v2 文档；旧版 / 未来版 / 损坏内容整体进隔离区，**原文逐字节保留、禁止自动覆盖**，可在界面导出后手工修复再导入——运行时不再提供 v1 自动迁移，这是明确的兼容性取舍），编辑即写回（拖动期间 500ms 节流 + 拖动结束强制保存）。浏览器通过 Web Locks 串行保存，并按最后读取的文档快照合并跨页面修改；不同动作各自保留，同一动作冲突的另一份完整文档进入隔离区供导出恢复，删除与编辑冲突时保留删除并隔离编辑稿。收到同步事件时保留尚未保存的本地修改。写入主库前先同步保存独立草稿（仅包含改过的完整文档和新增隔离稿）；草稿键不可变，先写入新快照才清理前一份，避免等待锁时强制关页丢失最新的成功快照。工作台页面用独立 Web Lock 标记存活，关闭或崩溃后浏览器自动释放；草稿记录所属页面，新页面跳过仍存活页面的草稿（含拖动节流期间尚未排队保存的草稿）。下次打开工作台在取得保存锁后，重新读取草稿与最新主库；正常保存已清理的草稿、已在主库中的相同文档不重复恢复，失去页面所有者且仍未提交的草稿移入隔离区（旧格式未标记所有者的草稿保守恢复），可「恢复为副本」继续编辑或导出 JSON；只有恢复内容已写入主库才清理原草稿。恢复保留文档内容，不重放未提交的删除或排序。顶部始终显示「保存中 / 已保存到本机 / 保存失败」，等待和失败时可直接导出当前动作 JSON。返回实验室会等待所有排队保存，失败则留在工作台；普通刷新、关页在未完成保存时请求浏览器离开警告。浏览器可能不显示警告，强制关闭依赖已成功写入的草稿恢复。不支持 Web Locks 时拒绝写入主库，保留可写入的草稿并显示失败及导出入口；自动草稿恢复同样等待成功取得保存锁。浏览器存储不可用或已满时无法保证草稿落盘，须按顶部失败提示导出备份。读取时逐条经 `validateDocShape` 严格校验（有限数值、严格递增时间、布尔约束、非退化方向框架），损坏或非法条目移入 `quarantine` 保留原文（可导出修复后再导入），全空时用示例动作重新播种；隐私模式 / 超限写失败时 `library.lastError` 置位且顶部明示「保存失败」及导出入口。
- 新建动作用 `blankDocument` 模板：站立姿态、双足支撑锁定、起始/结束两个关键帧，时长 1s。
- 动作库顶端显示高亮的「从预设开始」按钮和动作选择框，避免被较长的已有文档列表挤出首屏。预设下拉列出内置动作库中所有可编辑的关键帧预设（含球员正手）；点击后以完整动作轨迹建立独立副本并暂停在起始帧。可用下方新动作名称框命名，留空时使用预设名加「副本」。新文档与关键帧编号重新生成，姿态、约束、时序、坐标系及握拍侧保留，可继续拖动手柄、调整关键帧并自动保存。原预设和此前文档保留；创建后的首次撤销回到此前文档，重做回到副本，后续编辑沿用逐文档撤销。外部动画片段与动力学动作没有内嵌工作台轨迹，暂不提供此入口。
- 右侧「选中关键帧」设置区提供当前动作名称输入框；修改后自动保存，并进入当前动作的撤销 / 重做历史，预设副本创建后也可在此重命名。
- 预设编辑真实路径验收：启动 dev server 后，从仓库根执行 `node scripts/workshop-preset-qa.mjs`（可用 `HUMAN3D_WEB_PORT` 指定端口，`--out-dir` 指定证据目录）。覆盖列表筛选、副本与源轨迹一致、预设副本重命名及撤销重做、手柄拖动、左右标签切换与四肢末端 / 弯曲引导点输入、区间曲线选择及撤销重做、重复创建、刷新后的文档与骨骼恢复；该浏览器检查未进 CI。
- 右侧「选中关键帧」设置区顶部按「左侧调整 / 右侧调整 / 通用调整」切换。支撑、握拍、手腕、手臂、腿部与脚部等有左右侧别的项目在对应侧标签中；动作名称、关键帧信息、帧间曲线、触球事件、躯干与骨盆等共用项目在通用标签中。标签栏固定在上方，下方设置容器独立滚动。手臂末端控制标为「前臂（小臂）末端目标」，由 IK 联动大臂与前臂；肘部引导点控制弯曲方向。目标坐标以米写入现有关键帧字段，经同一求解、自动保存和撤销路径生效；支撑脚目标写入支撑开始帧，离地帧仍编辑摆动路径点。
- 选中关键帧的「帧间过渡」设置控制当前帧到下一帧的整段曲线：平滑（Hermite，默认）保留现有的限界曲线，线性按两端状态直接插值；循环动作末帧控制末帧到首帧的闭环区间。设置随起始关键帧保存、支持撤销与重做；关闭「生成中间帧」时曲线选择暂不生效。
- 左右设置区提供「大臂关节旋转」「前臂（小臂）关节旋转」，可前后摆动、水平摆动和轴向旋转；大臂旋转会携带小臂与手部移动，小臂旋转以肘为中心。肘部引导点继续用于固定末端的 IK 弯曲提示。通用调整的「自由手臂（全方向）」将 `freeArms=true` 保存到动作，允许肘与腕超出人体参考范围；关闭后恢复原限位。合理性检查与姿态包交付校验仍使用人体参考标准。
- 刷新后从已加载动作的真实关键帧 id 初始化选中状态；姿态控件写入前先定位到所编辑关键帧。若预览时间与选中帧不一致，面板提示两个时间；要编辑预览时刻可先添加关键帧。
- `导出 JSON` 输出**当前动作单文件**（`*.workshop.json`）；`导入` 接受裸文档或 motion-file 信封——`kind:'workshop-motion'` 的 `document` 经 `unwrapMotionFile` 解包取出（`clip-motion` 没有内嵌轨迹，明确报错），解析后加入动作库并选中，id 冲突自动重生成。

## 文件格式与导出

工作台有五个导出入口：前三个是源数据/交付契约/派生品，后两个是姿态审阅用的固定相机渲染品：

| 按钮 | 文件名 | 内容 | 备注 |
|---|---|---|---|
| `导出 JSON` | `<docId>.workshop.json` | WorkshopDoc v2：米制世界坐标、角度为度、时间为秒；关键帧含 `pose` 全部任务空间字段、`constraints` 和可选 `videoTime` | `导入` 载入同类文件或 motion-file 信封 |
| `导出姿态包` | `<docId>.<artifactId>.pose.json` | 规范姿态包（`spec/pose-package.schema.json` v2）：`buildPosePackageLocal` 本地求解，与 `POST /v1/motions {workshop-doc}` 同一条 `parseDoc → solveWorkshop → validatePosePackage` 管线，产物与响应对等（对等测试逐字节钉死） | 语义校验 422 时**不下载**，问题明细留在卡片上；需 https/localhost（`crypto.subtle`）；采样率 fps 1–60 进入制品 id |
| `导出 GLB` | `<docId>.<artifactId>.glb` | 同一求解结果烘焙成 glTF 动画（逐骨四元数轨 + root 位移轨，时间轴原样含非整数末段） | **派生品**：不承载身份契约——`animations[0].name` 与文件名借用 artifact id 便于对应（非内容寻址声明）；导出用干净重解析的 `human.glb`（编辑器里的球拍/材质不会烘进去），共享 `packages/motion-core/src/glb-export.ts`，Node 侧 `npm run package-to-glb` 走同一转换器 |
| `渲染静帧` | `<docId>.t<秒>.png` | 当前时刻姿态的确定性渲染（`WorkshopEngine.captureStill`）：固定相机预设（默认 45°，相对该时刻骨盆根定位）+ 固定 640×720 PNG，pixelRatio 钉 1、不随视口/轨道漂移；内部 `暂停 → 快照 time/playing/相机/叠加物可见态 → seek+solve+render+toBlob（同任务内）→ 原样恢复`，`preserveDrawingBuffer` 保证读回 | 编辑器叠加物（手柄/轨迹线/触球标记/洋葱皮/重心支撑）**默认不入图**——直切 `Object3D.visible`，不走 options/docDirty（不触发 rebuildAux）；`opts.overlays:true` 可保留 |
| `关键帧拼图` | `<docId>.sheet.png` | 逐关键帧时刻一格静帧拼 contact sheet（`captureSheet`）：默认全部键时刻，>12 键 `sheetTimes` 均匀抽样 12 格且首尾帧必保留；4 列网格，每格下方 `t=…s` 标注带 | 每格与单张静帧共用同一渲染管线（同相机预设、同尺寸、同叠加物策略）；整张拼图跑在同一段外层捕获会话里——`capturing` 深度计数从入口持有到拼图 toBlob（格间不回落），压住 animate 循环的叠加物重建与画布拖动；程序化并发导出由 `CaptureMutex` 直接拒绝 |

五个导出共用同一份当前文档；姿态包与 GLB 由 `solvePackage()` 统一求解，fps 改动会得到不同 artifact id（不同文件名）；静帧与拼图不携带 artifact 身份，只是姿态审阅图。

内置动作不放在浏览器动作库里，而是按 motion-file 信封（`schemaVersion:1`）存于 `assets/motions/*.json`，由 `assets/motions/motion.schema.json` 与 `normalizeMotionFile` 双侧校验：三种 kind 的轨迹载体互斥——`kind:'workshop-motion'` 内嵌 `document`（与导出的 WorkshopDoc 同构），`kind:'clip-motion'` 指向外部动画片段（`clip.url`，如 walk），`kind:'dynamics-motion'` 携带 `dynamics.action` 肌肉动作参数与 `dynamics.records` 记录 URL（如 punch、baseball-throw）；dynamics-motion 还禁写 `document`/`clip` 与一切显示字段（name/duration/phases/capabilities 等由 `dynamics.action` 派生，`unwrapMotionFile` 与姿态包管线对它显式拒绝）。工作台与服务共用同一条 `normalizeMotionFile → frameAt → solveEffectiveFrame` 求解管线，因此内置动作的姿态与服务交付的姿态包同源。

## 实验功能：约束轨迹生成

「约束轨迹生成」在 `packages/motion-core/src/generate.ts` 中对真实 WorkshopDoc 采样与真实 HumanRig 求解进行确定性局部搜索。搜索空间限于关键帧时间重排和指定姿态通道相位重采样；不新增或删除关键帧、不改姿态约束、不重写文档级字段。触球键始终锁定，用户可额外锁定任意键；首尾键默认锁定。前后端调用共用同一生成器和 `quality-probe.ts` 指标实现。

候选必须先通过硬门禁：文档形状、键集合、文档字段、约束模式、锁定键、球拍握拍侧及实际挂载身份、拍头触球位置、支撑点、求解检查都保持有效；报告采样率下的代价还必须严格低于源动作。超限帧由真实逐帧 `analyzePose` 结果计数，不能靠平滑代价抵消。搜索评估预算默认 120 次（含源测量与报告），扫掠默认最多 4 轮；fps 限 1–240、扫掠硬上限 16、估算求解采样总量硬上限 300,000 帧。

面板把候选保留在易失预览态：Worker 加载同一份人体与 rig 资产并计算，页面保持可切相机；A/B 切换共享播放时刻和相机。取消终止 Worker、丢弃候选，且不改动作库、持久化字节或撤销书。保留会创建新的动作 id 和关键帧 id，再进入现有库；「保留并导出 JSON」导出该新文档。保留后的撤销可回到源动作，重做可回到候选。Worker 失败显示错误，不退回主线程跑搜索。

指标会记录末端 / 球拍 / 手腕加加速度、骨骼峰值角速度与世界向量角加速度、触球偏移和速度、支撑 / IK 残差、地面穿透、超限帧数，以及各链条峰值出现时刻。无球拍或无接触事件时，对应 tip / contact 指标会省略，不显示伪造的零。路径长度、峰值速度、峰值时刻和时序调整量是供人工判断的读数，不自动解释成更好或更差。接触速度下降可能伴随平滑改善，因此目标函数也不等价于竞技效果。界面上的「改善 / 中性」只是基于代价比和少数主指标的实验性数值判断，**不证明动作自然，也未经过运动员或教练评审**；所有候选都应通过同视角 A/B 检查，保留按钮由用户决定。

离线入口：`npx tsx scripts/generate-motion.mts [forehand|squat|forehand-detuned|squat-detuned|all]`。四份 `evidence/generate-*.json` 保存源 / 候选完整度量、门禁结果和候选文档；`evidence/generate-forehand-ab.png` 是真实工作台同视角截图。forehand 样例中末端积分 jerk 从 982.09 降至 510.56 m/s²、角 jerk 从 9679.89 降至 5329.73 rad/s²，触球偏移保持 0 mm；detuned forehand 也能恢复显著平滑读数。下蹲样例被标为 neutral；一个受损下蹲样例在报告采样率上退化，因此明确拒绝。这些数值是有限样本上的实现证据，不是普遍质量或自然度结论。

## 边界

- 不做动力学：没有质量/惯性的真实积分、没有肌肉。合理性检查是运动学近似（de Leva 式分段质量分数）。
- 补间是限幅 Hermite（位置/角度通道）+ SO(3) 三次（手部朝向），不做连续优化或滤波；实验生成器只在有限时间 / 通道相位邻域里搜索，不作自然动作判定。导出只含关键帧与约束，不含烘焙轨迹。质量度量走 `packages/motion-core/src/quality-probe.ts`（CLI：`npx tsx scripts/measure-quality-probe.mts`，校准基线在 `evidence/quality-probe-*.json`）。
- 手部 forward/normal 通过增量滑杆编辑；拖动平面默认面向相机。支撑脚锁定在地面高度拖动；离地脚可三维拖动（相机朝向平面）或在右侧面板用「抬升高度」滑块精确设置 `foot.target.y` —— 该高度即摆动路径点。离地帧时刻脚骨骼仍在上一个接触点，因此摆动区间内脚柄只作显示；青色「摆动路径点」手柄直接绑定离地帧存储的 `foot.target`，拖动它即编辑轨迹中点。末尾离地帧没有后续区间，面板会提示先添加落地帧。
- 与查看器共用 `rig/kinematics/racket` 模块；`gripFrame`/`mountRacket`/`applyGrip`/`blendGrip` 均接收 `side` 参数（缺省 `'R'` 保持旧语义），左挂载是右挂载的精确 x 镜像（手腕局部系在静止位形下与世界系同轴，位置 x 取反、四元数 y/z 取反）。工作台动作不进入主页动作库。
