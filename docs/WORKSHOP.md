# 动作工作台（Motion Workshop）

状态：已实现最小可用版（`workshop.html`），轨迹优先，不依赖 MuJoCo 动力学。

首次打开时从中立站姿的空白动作开始。工作台不提供内置预设动作或预设副本入口；已有本地动作、导入/导出与用户保存的姿态继续可用。

## 为什么先做轨迹而不是肌肉

查看器接入 MyoSim/MuJoCo 的正向链路是「肌肉激活 → 关节力矩 → 物理积分 → 动作」。但动画素材与运动分析真正需要的是**动作轨迹**：先有目标姿态再倒推肌肉收缩，会立刻撞上逆动力学、肌肉冗余控制（数百条肌肉 ↔ 几十个自由度）和运动规划三个难题，仅靠手工关键帧无法唯一确定驱动方式。

MyoSuite 官方文档本身就把运动回放（joint-angle trajectory replay）、逆运动学、逆动力学、正向模拟分成不同操作——载入关节角轨迹回放不要求从肌肉激活开始。

因此工作台把管线重排为：

| 阶段 | 方法 | 需要动力学 |
|---|---|---|
| 手动调整关键姿态 | 任务空间拖动 + 解析 IK | 否 |
| 生成连续动作 | 关键帧区间可选平滑 Hermite 或线性补间 + 约束保持 | 否 |
| 更自然的动作 | 参考视频对照（后续：WHAM/Motion Prior） | 否 / 可选 |
| 物理合理性 | 关节限位、支撑脚锁定、重心投影检查 | 运动学近似即可 |
| 真正肌肉控制 | MuscleMimic / 物理模仿学习 | 是 —— 后续阶段，不重造 |

MuscleMimic（amathislab/musclemimic）已提供全身肌肉驱动模仿学习实现与预训练检查点；当轨迹确认后再把「哪些肌肉实现了这个运动」交给它，而不是手工推激励。

## 交互模型

**1. 画布拖动与关节旋转并用。** 手腕、脚踝、骨盆、拍头和膝部都是可拖动手柄；手腕与脚踝命中后由 IK 解算整条肢体，肩、肘、腕也可在左右调整页旋转。膝部屈伸直接拖动膝手柄：双脚稳定支撑且前后错开时，下拖后膝会降低骨盆并让躯干后倾，再下拖前膝会让躯干回直；其他姿势下，上拖弯膝、下拖伸膝。每个候选经采样器、骨盆排程和求解器验证；超出限位、脚锚漂移、脚底入地或手腕目标变得不可达时会保留最后有效预览。膝极点不作为任意 XYZ 控件暴露。拖动写入当前或自动新建的关键帧（auto-key）。

**2. 关键帧携带约束而不只是姿态。** 每个关键帧记录：

- `plantL / plantR`：支撑脚锁定。连续的 `plant=true` 关键帧构成一个**接触区间**：整个区间内脚保持在区间起始帧的接触位置（后续锁定帧存储的脚位被忽略——接触是约束不是姿态采样）。移动支撑脚必须先经过一个 `plant=false` 关键帧（离地），再声明新的 `plant=true`（重新接触），或让该帧携带 `replant`（见下）。离地帧时刻脚仍位于上一接触点（保证连续），但**离地帧存储的脚位不会被忽略——它作为摆动路径点**：脚从接触点出发，在区间中点经过该存储姿态，再到落地帧接触点。默认平滑 Hermite 模式下切换处速度连续；选线性时速度可能在关键帧或摆动中点改变，但位置仍连续。
- `replant`：可选布尔约束，只在支撑帧上有意义——声明该帧的支撑脚锚定**自身存储的接触位**（target/yaw/pitch），即使前一帧也在支撑也把上一条接触区间在此断开；前段区间向新接触位平滑过渡。归一化时会把不可能生效的 `replant`（没有「支撑且前帧支撑」的侧）折叠掉。目前由「复制帧」写入：复制的支撑帧由此拥有自己的接触、与原帧互不牵连。新接触点相对前一接触点平面移动超过 10cm 时，工作台在脚部控件旁提示该段可能看起来像滑步，并建议插入离地阶段。
- `grip`：握拍约束（侧别由文档级 `gripSide` 决定）→ `applyGrip` 包裹该侧指节、球拍挂载到该侧手腕。包裹从该手当前手型（见「手指开合」）插值，握拳仍握住拍柄。动作属性中可设置文档级 `gripBevel`（选择贴掌的八棱面）和 `gripTilt`（拍柄相对手掌倾斜 −45° 至 45°），调整球拍方向不需要把手腕扳到极限。
- `contact`：触球/接触事件 → 拍头在该帧的世界位置显示为黄色标记，直接拖动标记即调整该帧手部目标让拍头到达该点（写入握拍侧的手部目标）。

约束属于关键帧并随 JSON 导出——生成器由此知道动作的**目的**（支撑、接触时刻），不只是身体形状。

**3. 参考视频并排。** 本地视频载入（不上传），帧步进、「对齐」把视频时间轴对齐到动作时间轴、可同步播放；每个关键帧可记录其对应的视频时间，形成视频关键帧清单。WHAM 类单目 3D 重建是后续接入点（遮挡、深度歧义需人工修正），当前以人工对照关键帧为主。

**4. 洋葱皮对照。** 「显示」卡片开启后，编辑视图叠加相邻姿态的幽灵骨架线框（`LineSegments`，非克隆 SkinnedMesh）：`keys` 模式取播放头前后各 N 个真实关键帧时刻（`sortedKeys` 括号定位，压在播放头下的键不幽灵化——那是正在编辑的实姿态），`step` 模式取 `t±k·Δt` 随播放头每帧跟随。每个幽灵时刻走与轨迹采样相同的 `frameAt + solveEffectiveFrame` 真实求解路径再逐骨记录世界位置。前帧冷色、后帧暖色、按距离衰减透明度，`depthTest:false`、renderOrder 8（低于手柄的 20）、不进拾取集合。每向最多 3 层——120 键文档不会被全键幽灵化；重算挂在 `docDirty`/`rebuildAux` 节奏上，幽灵时刻签名不变则跳过重解算，拖动中冻结。开关与参数是会话态，不写入动作库。「显示」菜单另有「拍柄棱面编号」：握拍时在拍柄八个棱面上叠 1–8 数字 sprite（随拍转动），用于对照选择贴掌面（见「动作属性 → 棱面」）。

**5. 审阅 / 编辑与手机布局。** 桌面和手机默认审阅，左右面板按需打开；轨迹、重心和洋葱皮默认关闭。进入编辑后可从左侧、右侧或通用调整页旋转关节并精调肢体。审阅模式隐藏手柄、锁定姿态控件，单指旋转、双指缩放/平移只操作相机；编辑模式才可拖手柄，触摸命中区为 28 px。窄屏（≤760px 或触屏短边横屏）以三维画布为主，动作与调整面板改为底部抽屉；相机选项和快捷条可横向滑动并避开安全区。时间轴关键帧命中区为 32×48 px，横向拖动 6 px 后才重定时，另有上一/下一关键帧按钮；底部播放控件横向滚动，主要触控目标至少 44 px。

**6. 关节旋转与姿态微调。** 左 / 右面板提供肩部三轴旋转、肘屈伸、腕部旋转和手型；可结合画布手柄调整 IK 末端与肘部弯曲方向。通用面板提供躯干、骨盆与头部旋转。膝部屈伸由画布上的膝手柄拖动；双脚稳定支撑且前后分腿时，膝手柄也可调节重心与躯干倾角。独立的语义动作面板已从工作台移除。

**7. 审阅反馈。** 「审阅反馈」卡按关键帧标记部位与问题（手臂穿身、拍头方向、支撑脚漂移等），复制为结构化 JSON 交给 agent；仅存于会话，不写入动作文档。

**显示皮肤。** 实验室与工作台的人体表面使用肌肉分区着色（`apps/web/src/theme/anatomy-skin.ts`：按蒙皮主骨与法线分组、肌腹向肌腱渐变、分界沟槽、纤维条纹）。这是展示近似，不是解剖图谱；几何、权重、求解与导出不变（GLB 导出重新解析干净模型）。

## 数据与求解

- `packages/motion-core/src/document.ts`：`WorkshopDoc` = 关键帧数组 + 时长 + 补间开关。姿态是任务空间参数（根骨偏移/朝向、脊柱前倾/转体/侧弯、四肢末端目标 + 极点 + 手部 forward/normal 框架、脚部 yaw/pitch）。`samplePose` 按数据性质分别插值：位置量做非均匀 Hermite（Catmull-Rom 中心差分切线，每个内部键限界 `|m| ≤ 2×相邻较小割线幅值`（`TANGENT_SECANT_CAP`）——抑制稀疏键的样条过冲/鞭打，端点与锁定通道仍取零切线，保持 C¹）；yaw/foot yaw/pitch 等角度先沿关键帧链做 ±360° 展开再走最短路径；手部 forward/normal 契约上必须是正交归一框架（seed/parse/库存恢复时规范化），按 corrected-slerp 形式的 SO(3) 三次曲线插值（逐位过键、键时刻角速度 C¹，切线与 `tan()` 同一构造与同限界）保证中间帧始终构成有效方向；支撑脚按上一条接触区间规则保持。
- `packages/motion-core/src/solver.ts`：采样帧的唯一求解入口是 `solveEffectiveFrame`（支撑权重淡入淡出、握拍渐变、抬肩辅助随帧传入，不再单独推导），落到 `solvePose` 把参数写到骨架（复用 `rig.limb`/`rig.hand`/`applyGrip`，含支撑脚背屈超限时的骨盆后移二分修正）。`analyzePose` 输出运动学合理性：膝/肘/肩限位、支撑脚残差、分段质量近似质心在支撑多边形（锁定脚脚印凸包）内的投影。
- `apps/web/src/workshop/engine.ts`：Three.js 场景、手柄拾取与拖拽平面、轨迹线（拍头/手腕）、触球标记、质心投影与地面支撑多边形。
- `apps/web/src/workshop/WorkshopApp.tsx`：文档/视频/约束/检查面板 + 关键帧时间轴。播放控制旁的「总时长」输入按比例调整关键帧时间（循环动作保留接缝间隔），范围为 0.2–10 秒；提交后可撤销。
- `mirrorDoc`（`document.ts`）整档镜像：以 x=0 平面（该骨架左=+X、右=−X）把同一动作换边——右手正手变左手正手。逐键约定：`root.x`、骨盆 `yaw`、`chest`/`side`（YXZ 中的 Y/Z 分量）与脚 `yaw` 取反，`lean`、脚 `pitch` 保持；`handL⇄handR`、`footL⇄footR` 对调且 target/pole/forward/normal 全部 x→−x（正交框架逐位保持）；`plantL⇄plantR` 对调使接触区间挪到另一侧脚（接触点、离地帧摆动中点经同一存储重写随动镜像）；`handFrames` 随手换侧（惯用的双手 pelvis 配置下等价于不变）；`gripSide` R↔L 翻转（镜像回右手时写回规范缺省形态）；`clavicleLift`、`loop`、`duration`、`inbetweens`、键时间/标签/`videoTime` 原样保留；`id`/`name`/`english` 追加可回切的镜像标记（`.mirrored` / ` · 镜像` / ` · MIRRORED`）——再镜像一次逐字节回到原文档。文档卡「镜像动作」按钮把镜像文档作为**新动作**入库并选中（原文档保留），且在新文档的撤销书上预存源文档快照：一步撤销即回到镜像前的文档（选择跟随恢复的 id；重做对称地回到镜像文档）。跨文档恢复是**指针语义**：只切换选中，快照内容绝不写回异 id 文档——否则镜像后对源文档的新编辑会被旧快照无提示抹掉。`mirror.test.ts` 在真实 `frameAt → solveEffectiveFrame` 路径上逐骨断言世界位置/朝向互为 x 镜像（实测位置残差 ≤2.8e-15 m、朝向 ≤6e-8 rad），随机文档与 shipped 资产同口径覆盖。

## 动作库与存储

工作台与实验室共用本机动作库。手工编辑会自动保存，也可点击「保存到动作库」确认；保存的动作出现在实验室动作库顶部，可播放、回到原文档继续编辑或删除。工作台不显示内置动作预设；首次打开或没有可恢复动作时，从中立站姿的空白动作开始。实验室只读加载不会创建默认文档或覆盖损坏数据。

### 导入、备份与恢复

「动作」面板中的「导入动作 / 导出动作」往返可继续编辑的 H3D JSON。「备份全部」包含动作、自建姿态与隔离原文，不改原库。「从备份恢复」限 64 MB，校验后先预览，再选择合并或替换；损坏的姿态/隔离容器整份拒绝，无法解析的动作则保留原文进隔离区。合并保留双方，重复动作 ID 重建帧 ID。仅含姿态或隔离项的备份也可恢复，空动作列表会建立空白工作区。

「替换全部」是两步：先下载当前数据的快照并要求勾选「已确认快照文件已保存并可打开」，才允许提交——下载调用返回不等于文件已落盘，所以这一步是用户对文件的确认，不是程序担保。替换本身还会在 IndexedDB 快照库写入一个恢复点（`kinesis-workshop-restore-point`，只存快照库、不占 localStorage 配额），与动作库、姿态键在同一次锁定事务里提交：替换生效就意味着恢复点已生效。恢复点**在锁内按最新规范快照生成**（不是本页内存）：另一个页签刚保存、本页还没收到 `storage` 事件时，那次保存照样进恢复点；因此替换不会因为「其他页面已更新」而中止（替换内容只来自备份文件，没有可被覆盖的本页数据），而合并仍会在这种情况下中止并要求刷新。恢复点刷新后仍在，面板显示「撤销替换」；撤销会把替换前的动作和姿态恢复到刚读取的备份，替换后新增或改过的动作移入隔离区、姿态以新编号保留，两边都不丢。恢复点不可读时不提供撤销，只能使用替换前下载的 JSON。

动作与姿态通过平台多键锁和同一个 IndexedDB 事务提交，localStorage 为兼容镜像；配额或事务失败时保持旧库。成功替换会清理被替换文档的撤销书，避免同 ID 的旧历史覆盖恢复结果。自建姿态普通保存也使用相同快照路径，返回实验室会等待两类保存完成。

恢复点的提交、锁内快照与跨页面冲突由 `library-backup.test.ts` 的 `restore point commits with the replace` 覆盖（含「另一个页签保存但本页未同步」的竞争窗口）；真实 UI 回归包含在 `npm run qa:library` 里（勾选门禁、刷新后撤销、撤销保留双方、未同步窗口），CI 的 `browser-qa` workflow 跑同一入口。

真实 UI 回归：`npm run qa:library`（需 dev server；桌面 + 手机模拟，单页串行）。它依次跑 `library-backup-qa.mjs`（冲突、异常文件、配额/事务失败、新浏览器往返、替换门禁与撤销）和 `library-concurrency-browser-qa.mjs`（独占锁、跨页签保存、未同步窗口下的替换与撤销）；CI 的 `browser-qa` workflow 跑同一入口。单独跑某一项：`sh scripts/check-process-limit.sh && node scripts/library-backup-qa.mjs --out-dir <仓库外目录>`。

### 拼接与混合

左侧「组合动作」只从动作库中的其他自建或导入动作选择来源，再选择组合方式和可选名称，点击「拼接并保存 / 混合并保存」创建新动作。两份源文档保留；新文档沿用镜像动作的撤销规则，第一次撤销切回源动作，后续编辑可正常撤销。

- 前后拼接：当前完整动作 → 0.1–2 秒过渡（默认 0.3 秒）→ 另一段完整动作。总时长超过 10 秒时拒绝，源动作不变。
- 按比例混合：两段动作按归一化进度对齐，取较长时长；滑块指定另一段占比。0% / 100% 是对应源的独立副本；其余比例生成不循环的关键帧动作。支撑仅在双方都支撑时保留；握拍与触球事件取占比高的动作，50% 取另一段。
- 组合使用生产采样器读取姿态、短弧角度和手腕旋转，再以最多 120 帧重建可编辑文档；优先保留支撑 / 握拍切换和触球时刻，空间充足时保留源关键时刻，额外采样最高约 12 Hz，因此中间轨迹为近似值。离地键存储下一小段的摆动中点，持续支撑保持锚定。结果移除源视频时间标记。
- 一个文档只有一套自由手臂、锁骨辅助和持拍侧设置。两段策略不一致、或双方均持拍但侧别相反时，提示先统一设置 / 镜像；必要的约束切换与触球时刻合并已超过 120 帧时拒绝。外部剪辑和动力学回放没有可编辑文档，不列入组合来源。
- 保存仍使用同一本机动作库，存储不可用或已满会明确报告失败；内存中的组合结果可导出 JSON 备份。

### 关键帧管理

左侧「关键帧」列表按时间排列，可滚动查看整段动作。点击一帧会暂停播放并定位到该帧；右侧三个调整页共用「帧名称」「时间 s」「顺序」字段，名称同步显示在列表、时间轴与阶段标签中。时间在失焦或按 Enter 后提交，Escape 取消本次输入；不能与其他帧重时，循环首帧固定在 0s。

- 「当前时刻添加」保存当前采样姿态；该时刻已有帧则直接选中。显式添加按 1µs 容差判重，不会被拖动自动建帧的 20ms 吸附吞掉。
- 「在选中帧后插入」在选中帧与下一时间点之间采样新增；已到动作末端时可延长 0.2s，最长仍为 10s。最多 120 帧，在写入入口拒绝超限。
- 每行的复制按钮或「复制选中帧」会把源帧完整复制到后方，并自动选中副本：姿态、约束、出段曲线与视频参考均独立保留，名称追加「副本」，生成新 id。插入时间沿用上述规则，原帧和其他帧时间不变；复制与必要的时长延长共用一条撤销记录。源帧的支撑脚在副本上声明 `replant`（新接触）：副本锚定自身的有效接触脚位而不是并入源帧的接触区间——采样轨迹逐位不变，但副本的脚是可写的活数据，画布拖动与面板滑块都写入副本本身而不会跳到锚点帧。
- 列表的上移 / 下移与右侧「顺序」菜单保留原有时间槽，移动整帧的名称、姿态、约束、出段曲线和视频参考。直接修改时间则按新时间重新排列。
- 删除后至少保留两帧；循环首帧被删除时，下一帧移到 0s 保持循环锚点。删除选中帧后选中相邻帧。
- 插入、删除、换序及提交时间各自是一条撤销记录，连续点击也可逐步撤销；通过现有动作库自动保存与 JSON 导出保留。

### 球拍 · 我的姿态

关键帧列表下方保留球拍快速操作和用户自己保存的姿态，不提供内置动作一键插入：

- **球拍**：「右手持拍 / 左手持拍」把 `gripSide` 设为对应侧并给所有关键帧打开 `constraints.grip`（球拍全程显示）；「卸下球拍」清空全部握拍标志并把侧别归位默认；「本帧持拍 / 本帧放下」按选中帧当前标志原地切换 `constraints.grip`——空手段落从该帧起持拍，后续键的自有标志决定何时放下。均经结构编辑路径，一步撤销不与他操作合并。
- **我的姿态**：选中任意关键帧后「存当前姿态」把完整姿态（含手臂，不含约束）存入本机 `localStorage['kinesis-workshop-poses']`（重名自动编号，损坏条目读取时丢弃）；点击自建姿态把它写到播放头——该时刻已有帧则原位替换姿态（约束不变），否则插入新帧；右侧 × 删除。若目标帧的某侧脚是支撑区间的**非锚点成员**（前一帧也在支撑），该侧脚部的 target/yaw/pitch **不会被写入**（contactPlan 把整条通道锚定回支撑首帧，写了也不生效），提示里会如实列出，膝盖方向（pole）仍会应用；要移动支撑脚请先释放该帧支撑。**离地边界帧**（紧随支撑帧的 released 帧）则相反：离地瞬间脚仍从原接触点起步，但该帧存储的 target 是 `interpolate` 的摆动中点路点（contact → waypoint → 下一目标 的两段 Hermite），所以新目标会**写入并塑造离地后的摆动路径**；脚尖 yaw/pitch 没有路点机制、始终跟随支撑接触点（只改朝向的盖章不写入也不提示）。时间轴末尾的离地帧（后面没有摆动区间）按支撑成员处理。提示会说明这一语义区别。完全支撑的循环动作首帧是锚点、可正常编辑。「粘贴姿态」与「我的姿态 → 应用」共用同一套盖章语义（`stampPoseIntoKey`）。应用被关键帧上限拒绝时不产生撤销记录。「复制姿态 / 粘贴姿态」是会话内剪贴板，跨帧、跨动作均可粘贴。「镜像姿态」把选中帧左右镜像（`mirrorKey`：手脚与支撑互换；左右手坐标系不同时拒绝并提示改用整档「镜像动作」）。`gripSide` 是文档级属性，单帧镜像**不换**握拍侧（球拍仍挂在原侧手上，其他帧的握拍求解不受影响）；要整档换边请用「镜像动作」。动作库被删除时自建姿态不受影响；写失败时提示「仅存于内存」。

工作台按**动作库**组织（`apps/web/src/workshop/library.ts` 的 `MotionLibrary`）：

- 每个动作是一份 `WorkshopDoc`（`schemaVersion:2`）：`id`（按名称生成 slug + 随机后缀，冲突时重新生成）、`name`（自定义命名）、`english`、`duration`、`inbetweens`、`loop`（周期性接缝）、`handFrames`（手部目标按 world / pelvis 系插值）、可选 `clavicleLift`（抬肩辅助：握拍侧手部目标抬高时锁骨与肩带随动上抬，求解器逐帧推导幅度——内置 reach 动作使用，面板「抬肩辅助」开关）、可选 `gripSide`（握拍侧 `'R'|'L'`：缺省即右手且为规范形态——显式 `'R'` 在 `normalizeDoc` 归一化时折叠回缺省，因此同义写法共享指纹；`'L'` 把整套握拍阶段——`applyGrip` 指节包裹、腕弯曲限位、抬肩辅助、球拍挂载——镜像到左手，面板「握拍侧」下拉。侧别改变求解出的轨迹，所以它属于文档并进入请求指纹，不是展示元数据）、可选 `gripBevel`（拍柄棱面 1–8 整数，缺省 1 = 默认贴掌面并在 `normalizeDoc` 折叠；编号手掌相对、左右编号方向镜像，所以 `mirrorDoc` 原样保留、同一号码换手同握法。它选择贴掌/虎口的八棱面；手指包裹与球拍共用握把方向，作为文档字段照常进入指纹与定义哈希，改棱面得到新 artifact id；面板「动作属性 → 棱面（贴掌面）」下拉，展示走 `presentation.bevel`，裁决见 ADR-0010）、`keys[]`。关键帧可带可选 `interpolation`（`hermite` / `linear`，缺省 `hermite`），控制本帧到下一帧的过渡曲线。每键姿态可带可选 `handSpread {L?,R?}`（手指开合 0–1：0 握拳、0.5 自然、1 张开；0.5 是缺省规范形态——写 0.5 即删通道，旧文档字节不变；随姿态过同一 Hermite 采样器，握拳锚点取自 rig 的 punch 拳型；通道追加在 `flattenPose` 尾部，旧通道索引不动；「手指开合」滑块见下方左右设置区；手型移动指节骨骼，属运动语义，`SERVICE_VERSION` 已随之升至 0.9.0）。
  - `gripTilt`（拍柄倾斜 −45°..45°，缺省 0°）：动作属性滑块设置；正值让拍头朝掌面前方倾斜，镜像时保留角度。手腕姿态保持不变，握拍手指会跟随倾斜后的八棱柄轴包裹；相应的拍头接触标记与拍头度量也会变化。字段随文档进指纹，姿态包的 `presentation.gripTilt` 供播放器还原，详见 [ADR-0011](decisions/0011-racket-grip-tilt.md)。
- 每键姿态可选 `headYaw` / `headPitch`（单位度，缺省 0）相对颈部旋转头骨，范围分别为 −80°…80° 与 −45°…45°；正 `headYaw` 朝模型左侧，正 `headPitch` 低头。它们进入采样、求解与动作指纹，镜像时 yaw 取反、pitch 保持；旧文档默认头部不额外转动。
- 脚俯仰：正值让脚尖向下，支撑时踮脚、身体略微升高（最多 25mm）；负值让脚尖向上，由后跟支撑且不改变身体高度。滑块改变朝向时会保持脚底高度，求解器也会将意外低于地面的脚底抬回地面。
- 动作库主快照存于 IndexedDB `kinesis-workshop` / `snapshots`，JSON 镜像为 `localStorage['kinesis-workshop-library']`：`{schemaVersion:2, activeId, docs[], quarantine[]}`（只接受 schemaVersion 2 的容器与 v2 文档；旧版 / 未来版 / 损坏内容整体进隔离区，**原文逐字节保留、禁止自动覆盖**，可在界面导出后手工修复再导入——运行时不再提供 v1 自动迁移，这是明确的兼容性取舍），编辑即写回（拖动期间 500ms 节流 + 拖动结束强制保存）。首次无 IndexedDB 快照时从原 localStorage 导入，保留原 JSON 格式；升级后应刷新旧版本工作台页面再继续编辑。浏览器通过 Web Locks 串行保存，在锁内读取 IndexedDB 已提交快照，事务提交完成后更新 JSON 镜像、标记已保存和清理草稿（localStorage 跨渲染进程缓存即使加锁也可能滞后）。若主事务已提交但 JSON 镜像写入失败，顶部会说明主快照已提交并保留草稿；刷新仍能读取已提交版本。工作台启动、跨页同步与实验室读取同一已提交快照，并按最后读取的文档快照合并跨页面修改；不同动作各自保留，同一动作冲突的另一份完整文档进入隔离区供导出恢复，删除与编辑冲突时保留删除并隔离编辑稿。收到同步事件时保留尚未保存的本地修改。写入主库前先同步保存独立草稿（仅包含改过的完整文档和新增隔离稿）；草稿键不可变，先写入新快照才清理前一份，避免等待锁时强制关页丢失最新的成功快照。工作台页面用独立 Web Lock 标记存活，关闭或崩溃后浏览器自动释放；草稿记录所属页面，新页面跳过仍存活页面的草稿（含拖动节流期间尚未排队保存的草稿）。下次打开工作台在取得保存锁后，重新读取草稿与最新主库；正常保存已清理的草稿、已在主库中的相同文档不重复恢复，失去页面所有者且仍未提交的草稿移入隔离区（旧格式未标记所有者的草稿保守恢复），可「恢复为副本」继续编辑或导出 JSON；只有恢复内容已写入主库才清理原草稿。恢复保留文档内容，不重放未提交的删除或排序。顶部始终显示「保存中 / 已保存到本机 / 保存失败」，等待和失败时可直接导出当前动作 JSON。返回实验室会等待所有排队保存，失败则留在工作台；普通刷新、关页在未完成保存时请求浏览器离开警告。浏览器可能不显示警告，强制关闭依赖已成功写入的草稿恢复。不支持 Web Locks 或 IndexedDB 时拒绝写入主库，保留可写入的草稿并显示失败及导出入口；自动草稿恢复同样等待成功取得保存锁。浏览器存储不可用或已满时无法保证草稿落盘，须按顶部失败提示导出备份。读取时逐条经 `validateDocShape` 严格校验（有限数值、严格递增时间、布尔约束、非退化方向框架），损坏或非法条目移入 `quarantine` 保留原文（可导出修复后再导入），无可恢复动作时以中立站姿的空白动作开始；隐私模式 / 超限写失败时 `library.lastError` 置位且顶部明示「保存失败」及导出入口。
- 新建动作用 `blankDocument` 模板：站立姿态、双足支撑锁定、起始/结束两个关键帧，时长 1s。
- 首次打开工作台时创建中立站姿的空白动作，内置动作不会复制到工作台。用户可以新建、导入或复制自己的动作，并在动作库中继续编辑。
- 右侧「选中关键帧」设置区提供当前动作名称输入框；修改后自动保存，并进入当前动作的撤销 / 重做历史。
- 工作台真实路径验收：`scripts/workshop-authoring-qa.mjs` 由 CI 的 `browser-qa` 工作流执行，覆盖无内置预设、导入用户动作、独立副本、画布拖拽、左右关节旋转、肢体目标编辑、区间曲线、撤销重做和刷新后的姿态恢复。
- 膝盖手柄与单帧持拍真实路径验收：该路径由 CI 的 `browser-qa / library` 工作流执行。覆盖画布膝部拖动、双支撑重心调整、脚锚 / 支撑 / 手部目标保持、膝角限位与邻帧连续性；膝极点手柄与 XYZ 控件已移除，「本帧持拍 / 本帧放下」仅写选中帧且单步撤销整步还原。
- 右侧「选中关键帧」设置区顶部按「左侧调整 / 右侧调整 / 通用调整」切换。支撑、握拍、手腕、手臂、腿部与脚部等有左右侧别的项目在对应侧标签中；动作名称、关键帧信息、帧间曲线、触球事件、躯干、骨盆与头部朝向等共用项目在通用标签中。标签栏固定在上方，下方设置容器独立滚动。通用页的「头部朝向」滑块写入当前关键帧；编辑模式下同页签会在头部前方显示紫色拖动点，拖动同时调整左右转头和俯仰，并经同一求解、自动保存和撤销路径生效；拖点写俯仰时会反算求解器的躯干前倾补偿，确保头部方向跟随指针。手臂末端控制标为「前臂（小臂）末端目标」，由 IK 联动大臂与前臂；肘部引导点控制弯曲方向。目标坐标以米写入现有关键帧字段，经同一求解、自动保存和撤销路径生效；支撑脚目标写入支撑开始帧，离地帧仍编辑摆动路径点。左右设置区各有「手指开合」滑块（0–100%）：握拳 ↔ 自然放松 ↔ 张开，写入当前帧该侧 `pose.handSpread`；滑回自然（50%）即删除该侧通道（缺省即自然，不存半个默认值），读数按当前值标注握拳/自然/过渡中，与撤销/自动保存走同一路径。
- 选中关键帧的「帧间过渡」设置控制当前帧到下一帧的整段曲线：平滑（Hermite，默认）保留现有的限界曲线，线性按两端状态直接插值；循环动作末帧控制末帧到首帧的闭环区间。设置随起始关键帧保存、支持撤销与重做；关闭「生成中间帧」时曲线选择暂不生效。
- 左右设置区提供「大臂关节旋转」「前臂（小臂）关节旋转」：大臂为 `lift/swing/twist` 三通道绝对角度（肩是球关节，三者都可精确兑现），前臂只有一个可兑现的自由度「肘屈曲」（前臂方向与弯曲平面由腕部目标和肘部引导点反解，三轴伪绝对量已撤下）。大臂旋转会携带小臂与手部移动，小臂旋转以肘为中心。肘部引导点继续用于固定末端的 IK 弯曲提示。通用调整的「自由手臂（全方向）」将 `freeArms=true` 保存到动作，允许肘与腕超出人体参考范围；关闭后恢复原限位。合理性检查与姿态包交付校验仍使用人体参考标准。
- 刷新后从已加载动作的真实关键帧 id 初始化选中状态；姿态控件写入前先定位到所编辑关键帧。**播放头不在选中关键帧上时（含播放中），旋转滑块禁用**，面板提示当前时刻并提供「跳到该关键帧」一键对齐——读数与写入目标一致才允许拖动，避免第一次拖动时数值与模型突变。判据 `rotationControlsInSync` 有单测；真实 UI 断言由 CI 的 `browser-qa` 工作流执行。
- `导出 JSON` 输出**当前动作单文件**（`*.workshop.json`）；`导入` 接受裸文档或 motion-file 信封——`kind:'workshop-motion'` 的 `document` 经 `unwrapMotionFile` 解包取出（`clip-motion` 没有内嵌轨迹，明确报错），解析后加入动作库并选中，id 冲突自动重生成。

## 文件格式与导出

工作台有五个导出入口：前三个是源数据/交付契约/派生品，后两个是姿态审阅用的固定相机渲染品：

| 按钮 | 文件名 | 内容 | 备注 |
|---|---|---|---|
| `导出 JSON` | `<docId>.workshop.json` | WorkshopDoc v2：米制世界坐标、角度为度、时间为秒；关键帧含 `pose` 全部任务空间字段、`constraints` 和可选 `videoTime` | `导入` 载入同类文件或 motion-file 信封 |
| `导出姿态包` | `<docId>.<artifactId>.pose.json` | 规范姿态包（`spec/pose-package.schema.json` v2）：`buildPosePackageLocal` 本地求解，与 `POST /v1/motions {workshop-doc}` 同一条 `parseDoc → solveWorkshop → validatePosePackage` 管线，产物与响应对等（对等测试逐字节钉死） | 语义校验 422 时**不下载**，问题明细留在卡片上；需 https/localhost（`crypto.subtle`）；采样率 fps 1–60 进入制品 id |
| `导出 GLB` | `<docId>.<artifactId>.glb` | 同一求解结果烘焙成 glTF 动画（逐骨四元数轨 + root 位移轨，时间轴原样含非整数末段） | **派生品**：不承载身份契约——`animations[0].name` 与文件名借用 artifact id 便于对应（非内容寻址声明）；导出用干净重解析的 `human.glb`（编辑器里的球拍/材质不会烘进去），共享 `packages/motion-core/src/glb-export.ts`，Node 侧 `npm run package-to-glb` 走同一转换器 |
| `渲染静帧` | `<docId>.t<秒>.png` | 当前时刻姿态的确定性渲染（`WorkshopEngine.captureStill`）：固定相机预设（默认 45°，相对该时刻骨盆根定位）+ 固定 640×720 PNG，pixelRatio 钉 1、不随视口/轨道漂移；内部 `暂停 → 快照 time/playing/相机/叠加物可见态 → seek+solve+render+toBlob（同任务内）→ 原样恢复`，`preserveDrawingBuffer` 保证读回 | 编辑器叠加物（手柄/轨迹线/触球标记/洋葱皮/重心支撑）**默认不入图**——直切 `Object3D.visible`，不走 options/docDirty（不触发 rebuildAux）；`opts.overlays:true` 可保留 |
| `关键帧拼图` | `<docId>.sheet.png` | 逐关键帧时刻一格静帧拼 contact sheet（`captureSheet`）：默认全部键时刻，>12 键 `sheetTimes` 均匀抽样 12 格且首尾帧必保留；4 列网格，每格下方 `t=…s` 标注带 | 每格与单张静帧共用同一渲染管线（同相机预设、同尺寸、同叠加物策略）；整张拼图跑在同一段外层捕获会话里——`capturing` 深度计数从入口持有到拼图 toBlob（格间不回落），压住 animate 循环的叠加物重建与画布拖动；程序化并发导出由 `CaptureMutex` 直接拒绝 |

五个导出共用同一份当前文档；姿态包与 GLB 由 `solvePackage()` 统一求解，fps 改动会得到不同 artifact id（不同文件名）；静帧与拼图不携带 artifact 身份，只是姿态审阅图。

内置动作不放在浏览器动作库里，而是按 motion-file 信封（`schemaVersion:1`）存于 `assets/motions/*.json`，由 `assets/motions/motion.schema.json` 与 `normalizeMotionFile` 双侧校验：三种 kind 的轨迹载体互斥——`kind:'workshop-motion'` 内嵌 `document`（与导出的 WorkshopDoc 同构），`kind:'clip-motion'` 指向外部动画片段（`clip.url`，如 walk），`kind:'dynamics-motion'` 携带 `dynamics.action` 肌肉动作参数与 `dynamics.records` 记录 URL（如 punch、baseball-throw）；dynamics-motion 还禁写 `document`/`clip` 与一切显示字段（name/duration/phases/capabilities 等由 `dynamics.action` 派生，`unwrapMotionFile` 与姿态包管线对它显式拒绝）。工作台与服务共用同一条 `normalizeMotionFile → frameAt → solveEffectiveFrame` 求解管线，因此内置动作的姿态与服务交付的姿态包同源。

## 实验功能：约束轨迹生成

「约束轨迹生成」在 `packages/motion-core/src/generate.ts` 中对真实 WorkshopDoc 采样与真实 HumanRig 求解进行确定性局部搜索。搜索空间限于关键帧时间重排和指定姿态通道相位重采样；不新增或删除关键帧、不改姿态约束、不重写文档级字段。触球键始终锁定，用户可额外锁定任意键；首尾键默认锁定。前后端调用共用同一生成器和 `quality-probe.ts` 指标实现。

候选必须先通过硬门禁：文档形状、键集合、文档字段、约束模式、锁定键、球拍握拍侧及实际挂载身份、拍头触球位置、支撑点、求解检查都保持有效；报告采样率下的代价还必须严格低于源动作。超限帧由真实逐帧 `analyzePose` 结果计数，不能靠平滑代价抵消。搜索评估预算默认 120 次（含源测量与报告），扫掠默认最多 4 轮；fps 限 1–240、扫掠硬上限 16、估算求解采样总量硬上限 300,000 帧。

面板把候选保留在易失预览态：Worker 加载同一份人体与 rig 资产并计算，页面保持可切相机；A/B 切换共享播放时刻和相机。取消终止 Worker、丢弃候选，且不改动作库、持久化字节或撤销书。保留会创建新的动作 id 和关键帧 id，再进入现有库；「保留并导出 JSON」导出该新文档。保留后的撤销可回到源动作，重做可回到候选。Worker 失败显示错误，不退回主线程跑搜索。

指标会记录末端 / 球拍 / 手腕加加速度、骨骼峰值角速度与世界向量角加速度、触球偏移和速度、支撑 / IK 残差、地面穿透、超限帧数，以及各链条峰值出现时刻。无球拍或无接触事件时，对应 tip / contact 指标会省略，不显示伪造的零。路径长度、峰值速度、峰值时刻和时序调整量是供人工判断的读数，不自动解释成更好或更差。接触速度下降可能伴随平滑改善，因此目标函数也不等价于竞技效果。界面上的「改善 / 中性」只是基于代价比和少数主指标的实验性数值判断，**不证明动作自然，也未经过运动员或教练评审**；所有候选都应通过同视角 A/B 检查，保留按钮由用户决定。

离线入口：`sh scripts/check-process-limit.sh --npx && npx tsx scripts/generate-motion.mts [forehand|squat|forehand-detuned|squat-detuned|all]`。四份 `evidence/generate-*.json` 保存源 / 候选完整度量、门禁结果和候选文档；`evidence/generate-forehand-ab.png` 是真实工作台同视角截图。forehand 样例中末端积分 jerk 从 982.09 降至 510.56 m/s²、角 jerk 从 9679.89 降至 5329.73 rad/s²，触球偏移保持 0 mm；detuned forehand 也能恢复显著平滑读数。下蹲样例被标为 neutral；一个受损下蹲样例在报告采样率上退化，因此明确拒绝。这些数值是有限样本上的实现证据，不是普遍质量或自然度结论。

## 边界

- 不做动力学：没有质量/惯性的真实积分、没有肌肉。合理性检查是运动学近似（de Leva 式分段质量分数）。
- 补间是限幅 Hermite（位置/角度通道）+ SO(3) 三次（手部朝向），不做连续优化或滤波；实验生成器只在有限时间 / 通道相位邻域里搜索，不作自然动作判定。导出只含关键帧与约束，不含烘焙轨迹。质量度量走 `packages/motion-core/src/quality-probe.ts`（CLI：`sh scripts/check-process-limit.sh --npx && npx tsx scripts/measure-quality-probe.mts`，校准基线在 `evidence/quality-probe-*.json`）。
- 手部 forward/normal 通过增量滑杆编辑；拖动平面默认面向相机。支撑脚锁定在地面高度拖动；离地脚可三维拖动（相机朝向平面）或在右侧面板用「抬升高度」滑块精确设置 `foot.target.y` —— 该高度即摆动路径点。离地帧时刻脚骨骼仍在上一个接触点，因此摆动区间内脚柄只作显示；青色「摆动路径点」手柄直接绑定离地帧存储的 `foot.target`，拖动它即编辑轨迹中点。末尾离地帧没有后续区间，面板会提示先添加落地帧。
- 与查看器共用 `rig/kinematics/racket` 模块；`gripFrame`/`mountRacket`/`applyGrip`/`blendGrip` 均接收 `side` 参数（缺省 `'R'` 保持旧语义），左挂载是右挂载的精确 x 镜像（手腕局部系在静止位形下与世界系同轴，位置 x 取反、四元数 y/z 取反）。棱面是挂载后的局部后旋转（`bevelRoll`，绕柄轴 ±45° 整数倍、左右取反），数字标签锚点与方向由 core 提供（`bevelAnchor`/`bevelDirection`），sprite 绘制留在 web 层。工作台动作不进入主页动作库。
